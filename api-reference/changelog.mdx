The generated contract carries `info.x-darpan-contract-version`, decoupled from the product release version. The policy is additive-only: new methods, new optional parameters, and new response fields ship without a bump; breaking changes require a conscious one. See [Contract versioning](/api-reference/json-rpc#contract-versioning).

| Contract version | Darpan releases | Public `facade.*` methods |
| --- | --- | --- |
| 3 (current) | 1.5.0, 1.5.1, 2.0.0, 2.1.0, 2.1.1, 2.1.2 | 147 |
| 2 | 1.2.0, 1.3.0, 1.4.0 | 73 |
| 1 | 1.0.0 to 1.1.0 | 66 |

Releases 1.3.0, 1.4.0, and 1.5.1 added or removed no methods.

<Note>
Operator-only methods (`admin.*`) are listed in the [service catalog](/api-reference/service-catalog#administration) but are not part of the public API. They serve the operator admin application and require a super-admin caller, so integrations should not depend on them. The counts below mention them only so the totals add up.
</Note>

## Contract version 3

Darpan 1.5.0. Current.

### Added in 2.1.2

The facade contract stays at version 3: every 2.1.1 method, parameter and response field is unchanged, and 2 public methods are added (145 to 147).

- `facade.AuditFacadeServices.retry#AuditCheck`: re-runs one audit check that did not run on one morning, from the files that morning's run already read.
- `facade.ReconciliationFacadeServices.get#ActiveRunResult`: the active tenant's newest pending or running run of a saved run, begun in the last two minutes.

Rules gain two FIELD_COMPARISON operators, `all in` and `contains all`, for comma-separated lists; a rule's `expression` names them in `operator`.

### Added in 2.1.1

The facade contract stays at version 3: every 2.1.0 method, parameter and response field is unchanged, and 4 public methods are added (141 to 145).

- `facade.AuditFacadeServices.get#AuditProgress`: whether an audit's play is running, and how far its checks have got.
- `facade.ReconciliationFacadeServices.get#AutomationStreaks`: an automation's stored clean-day streak, its badges and side quests.
- `facade.ReconciliationFacadeServices.retry#AutomationExecutionFromExtracts`: re-runs a failed execution whose reads all finished, over the same window, from the files it already read.
- `facade.ReconciliationFacadeServices.repair#ConnectorRecordKeys`: adds the record root to the bare keys of a run's connector sources; `dryRun` lists the changes without saving them.

`facade.AuthFacadeServices.request#PasswordReset` returns two new fields: `outcome` (`sent`, `noAccount`, `locked`, `noEmail`, `overLimit` or `sendFailed`) and `emailAddressMasked`.

Five operator-only `admin.*` methods are added: `get#LiveOperations`, `get#TransferCatalog`, `export#ConfigBundle`, `import#ConfigBundle` and `begin#SecretHandoff`.

### Added in 2.0.0

The facade contract stays at version 3: every 1.5.1 method, parameter and response field is unchanged, and 29 public methods are added (86 to 115). The breaking change in 2.0.0 is at the transport, not in the contract: `/rpc/json` now refuses any method outside `facade.*`, `admin.*` and `gql.*` with HTTP 403 before dispatch, and the framework's `/rest/login` is closed. An integration that only calls the methods on this page needs no change. See [Errors](/api-reference/errors).

### Breaking change

- `facade.SettingsFacadeServices.list#TenantChatSpaces` no longer returns `chatSpaces[].googleChatWebhookUrlMasked`. Webhook URLs are now stored in clear text and returned in `webhookUrl` (and in `googleChatWebhookUrl`, the pre-Slack name).

### Added

- `facade.AuthFacadeServices.change#ExpiredPassword`

Anonymous by necessity, because the account cannot hold a session until the password changes. It requires the account's current password.

## Contract version 2

Darpan 1.2.0. Unchanged through 1.3.0 and 1.4.0.

### Removed

Replaced by the chat-space registry:

- `facade.SettingsFacadeServices.get#TenantNotificationSettings`
- `facade.SettingsFacadeServices.save#TenantNotificationSettings`

Callers reading or writing the single tenant webhook should move to `list#TenantChatSpaces` and `save#TenantChatSpace`. Existing webhooks are carried over automatically on upgrade. See [Run-completion alerts](https://docs.drpn.ai/guides/run-completion-alerts#upgrading-from-the-single-tenant-webhook).

Connections:

- `facade.SettingsFacadeServices.test#SourceConnection`

That is 9 public methods added and 2 removed. The release also added 17 operator-only `admin.*` methods.

## Contract version 1

Baseline contract, Darpan 1.0.0 (65 methods, all `facade.*`).

- JSON-RPC 2.0 transport over `POST /rpc/json`.
- Auth channels: HttpOnly `darpan_login_key` cookie plus CSRF token (browser, canonical) and `login_key` header (integration callers and fallback).
