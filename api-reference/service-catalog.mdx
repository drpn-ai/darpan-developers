description: "Verified backend facade services exposed through Darpan JSON-RPC."

Every method below is called as the JSON-RPC `method` value. The generated contract builds this list from the services marked for remote calls in `service/facade/` and `service/admin/` of the Darpan backend component, plus `service/facade/` of the integration components. `facade.*` methods are the public API. `admin.*` methods are operator-only and listed under [Administration](#administration); they are not part of the public API.

This catalog matches Darpan 2.1.0 (contract version 3).

All methods require an authenticated session unless noted. Eight methods accept anonymous calls, so a caller can establish or end a session or reset a forgotten password: `login#Session`, `logout#Session`, `get#SessionInfo`, `change#ExpiredPassword`, `request#PasswordReset`, `verify#PasswordResetCode`, `complete#PasswordReset`, and `get#PasswordResetStatus`.

## Auth (`facade.AuthFacadeServices`)

| Method | Purpose |
| --- | --- |
| `login#Session` | Create an authenticated session from username/password and return the login-key token. Anonymous. |
| `logout#Session` | Revoke the token on the current request and end that session only. Anonymous-safe. |
| `logout#AllSessions` | Revoke every login key for the current user, signing them out on every device. |
| `get#SessionInfo` | Return current session, user, and active-tenant context. Anonymous-safe. |
| `save#ActiveTenant` | Switch the caller's active tenant. The choice is stored on the user, not the session, so it applies to every session and tab of that user. The tenant key is the tenant's user group id (`companyUserGroupId` on tenant-owned records). |
| `save#UserSettings` | Save per-user settings, including display name and preferred display timezone (IANA id; empty string clears the preference). Returns refreshed session metadata. |
| `verify#OwnPassword` | Re-verify the current user's password. |
| `change#OwnPassword` | Change the current user's password. |
| `change#ExpiredPassword` | Change the password of an account that cannot sign in until it is changed, without a session. Requires the account's current password. Anonymous. Issues no token: sign in again afterwards. |
| `request#PasswordReset` | Email a 6-digit reset code to the email on file for a username or email address. The reply is the same in content and timing whether or not a code was sent (no such account, disabled, no email on file, over the hourly limit), so it does not reveal which accounts exist. The code expires in 15 minutes; a new request replaces it. Anonymous. |
| `verify#PasswordResetCode` | Check a reset code without using it up. Five wrong guesses end the code; wrong guesses do not count as failed logins. Every failure returns the same error. Anonymous. |
| `complete#PasswordReset` | Set a new password with a reset code, then sign the account out on every device and email it that the password changed. Password-policy failures are reported in full. A disabled account is refused and stays disabled. Anonymous. Issues no token: sign in again afterwards. |
| `get#PasswordResetStatus` | Whether this deployment can send reset email: true when the `SYSTEM` email server has an SMTP host and the reset-code email template is loaded. Anonymous. |
| `save#RecoveryEmail` | Set the signed-in user's recovery email, where reset codes go. Requires the current password; a wrong one counts as a failed login. Refused when another account already uses the address. The new address, and the previous one when it changes, get a notice. Returns the address masked. |

The password reset methods need the password reset email templates loaded and an email server configured on the deployment. Without both, no code is sent and `get#PasswordResetStatus` returns false.

### Runs as flowcharts (`facade.ReconciliationFacadeServices`)

A run is a flowchart of questions: each question is one reconciliation, and the questions under it run on its yes or no.

| Method | Purpose |
| --- | --- |
| `list#Reconciliations` / `get#Reconciliation` | The active tenant's runs, archived ones left out, or one run with its questions. |
| `save#Reconciliation` | Create or update a run. |
| `save#ReconciliationQuestion` / `delete#ReconciliationQuestion` | Create, update or remove one question. Tree rules are enforced on the server. A question with questions under it cannot be removed. |
| `run#Reconciliation` | Start a run. Returns the execution id at once; the walk continues in the background. |
| `get#ReconciliationExecution` | Every question's result from one execution. |
| `list#ReconciliationExecutions` | A run's past executions, newest first, each with a rolled-up status. |
| `import#NetSuiteChecksAsRuns` | Turn the tenant's NetSuite checks that are not yet in a run into runs, one per population. Safe to repeat; a check that cannot be placed is skipped with a message saying why. |

### Lifecycles (`facade.ReconciliationFacadeServices`)

A lifecycle follows records from a start record type through their stages, and reports where each one stopped.

| Method | Purpose |
| --- | --- |
| `save#Lifecycle` | Create a lifecycle from a NetSuite account, a start record type and its stages in order. The server writes the queries, rules and question tree. |
| `save#LifecycleStages` | Reorder or change a lifecycle's stages. Past results stay readable. |
| `save#LifecycleRule` / `delete#LifecycleRule` | Leave out start records whose field has a given value, or remove that rule. |
| `save#LifecycleStageException` / `delete#LifecycleStageException` | Mark a stage as not expected for records whose field has a given value, or remove that exception. |
| `save#LifecycleFinding` / `delete#LifecycleFinding` | Add or remove a finding: the records that reached a stage and match a field condition, reported in a place of their own. |
| `save#LifecycleDetails` | Choose the extra fields a lifecycle's records show beside the standard columns. Replaces the list. |
| `get#LifecyclePlan` | The places a start record type and an ordered list of stages would make, named as `save#LifecycleStages` names them. Saves nothing and does not call NetSuite. |
| `save#LifecycleConclusions` | Replace a lifecycle's ordered list of conclusion rules. Each rule names a conclusion, the places it applies to (none means every place), and field conditions (`IN`, `NOT_IN`, `BLANK`, `NOT_BLANK`) that must all hold. At each place the first rule that holds names the record; a record no rule names stays Unexplained. An empty list clears the rules. Lifecycles built from stages only. |

## Run conclusions (`facade.RunConclusionFacadeServices`)

A saved run's conclusion tree names the differences the run finds, by conditions on either side's record. Another tenant's run reads as not found.

| Method | Purpose |
| --- | --- |
| `get#RunConclusions` | A saved run's conclusion tree in order, the conclusion catalog the active tenant can use, and the condition vocabulary: buckets, operators, presence, key scopes and quantifiers. |
| `save#RunConclusions` | Replace a saved run's conclusion tree. All or nothing; an empty list clears it. Refused, with the reason, for an unknown conclusion, a parent not above its child, a tree deeper than three levels, a bucket on a nested conclusion, or a condition that does not say what it checks. Needs edit access on the active tenant. |
| `create#RunConclusionCode` | Add a conclusion code owned by the active tenant, named by its label (at most 100 characters). Only that tenant's catalog lists it. Refused when the catalog already has the label. |

## Audits (`facade.AuditFacadeServices`)

An audit is a set of statements about the active tenant's data, each tested by checks that run on a daily schedule and record findings. Reports and findings are returned as `darpan.audit.report/v1` and `darpan.audit.finding/v1` documents. Another tenant's audit or finding reads as not found. Writes need edit access on the active tenant.

| Method | Purpose |
| --- | --- |
| `get#Audits` | The active tenant's audits: id (the audit's code), name, and the period one report covers. |
| `create#Audit` | Create an audit from a name and a period (`day`, `month` or `quarter`). Its id is the name in lower case with dashes, unique within the tenant; `new` is refused. Statements and checks are added afterwards. |
| `add#AuditStatement` | Add a statement to an audit: the text that must be true, a category (`orders`, `refundsAndCredits`, `returns` or `exchangesAndWarranty`), and a weight (`firm`, or `derived` while awaiting the tenant's confirmation; default `derived`). It gets the next statement code, is placed last, and is active. |
| `get#AuditSettings` / `save#AuditSettings` | Read or change an audit's name, its statements' text and on/off state, and the daily schedule (time and time zone) its checks run on. A save sends only the statements that changed, creates a paused automation for any check whose run has none, and returns the settings as saved. The read also returns each statement's checks and the earliest day `run#Audit` can record. |
| `get#AuditCheckOptions` | What the add-a-check editor offers for one audit: its statements, the tenant's saved runs with their rules and conclusions, the row types and fix systems a check may name, and the audit's existing checks. |
| `save#AuditCheck` | Create or update a check and replace its links to the audit's statements; at least one link is required. All or nothing. Refused, with the reason, for a statement outside the audit, a run the tenant does not own, a rule not in that run, or a row type the check cannot record. A new check, or one whose run changed, has no automation until `run#Audit` or `save#AuditSettings` creates one. |
| `run#Audit` | Run every check of the audit now over a range of days, first to last inclusive, in the tenant's time zone, recording findings as the scheduled run does. Submitted in the background, one automation per run; returns each submission. Refused before anything runs for days in the future, a backwards range, or a period that ended and was not extended. With `fullRead`, every system is read for the whole range; without it, each check reads the days since its last complete read and re-checks its older open findings by key. |
| `get#AuditReport` | An audit's report for one day (default today in the tenant's time zone), optionally for one period's run, as a `darpan.audit.report/v1` document. |
| `get#AuditFindingsByOrder` | Every open and pending finding of one audit, one entry per order with its lines and the line holding it up, each with its statement and category. Filters by statement, period, and state (`open` or `pending`). State is as of today. |
| `get#AuditFinding` | One finding as a `darpan.audit.finding/v1` document: records, evidence, fix and history. |
| `verify#AuditFinding` | Re-check one finding's record now: its check runs for that record only, reading each system by key, and the finding is closed if the problem is gone or refreshed with today's cause. Submitted in the background; `get#AuditFinding` shows the result once `lastChecked` changes. Records no check run, so the check's health and next read are unchanged. Refused when the check has no automation yet. |
| `get#AuditCheckExtracts` | The files each system's read wrote for one check, day and period: one row per side with the system, the record count, and the file's data-manager path. Empty when the check has no recorded run for that day and period. |

## Slack (`facade.SlackFacadeServices`)

Connecting a Slack workspace to the active tenant. The bot token is never an output of any method here.

| Method | Purpose |
| --- | --- |
| `begin#SlackInstall` | Mint a single-use state token and return the Slack authorize URL to send the browser to. Does not contact Slack. Requires Slack app credentials on the deployment. |
| `save#SlackBotToken` | Connect a workspace from a pasted bot user OAuth token (`xoxb-`). The token is verified with Slack before storage, and workspace identity is taken from Slack's answer. |
| `get#SlackInstall` | The active tenant's connected workspaces, with granted scopes. Reports `oauthAvailable` separately from whether Slack is usable at all. |
| `list#SlackChannels` | One page of channels from a connected workspace, for the channel picker. Reports when a workspace holds more channels than are listed. |
| `disconnect#SlackWorkspace` | Deactivate a connected workspace. Refused while chat spaces still post through it, naming them. |

## Administration

<Warning>
Operator-only. The `admin.*` methods below are not part of the public API, and integrations should not depend on them. They serve the operator admin application and are reachable only by a super-admin: a caller must pass the `DARPAN_ADMIN_API` artifact fence and a super-admin content gate. A non-super-admin caller is denied before the service body runs.
</Warning>

## Per-method reference

The machine-readable contract for the public methods lives in the
[generated OpenAPI reference](/api-reference/openapi.json), regenerated from the backend
facade XML (`./gradlew :runtime:component:darpan:generateApiContract`). Backend CI runs
`scripts/check_service_catalog.py` from this docs repo against the generated method list
(`docs/api-contract/methods.txt`): it fails when this catalog names a method the contract
does not define, and only reports, without failing, contract methods the catalog does not
list. How to read the reference:

- Each method has four schemas in `components.schemas`, named from its verb#noun:
  `<VerbNoun>Params` (request parameters, with `required` markers), `<VerbNoun>Result`
  (the response payload the hand-written UI types model), and the `...Request`/`...Response`
  JSON-RPC envelopes around them.
- Parameter and field descriptions come straight from the service definitions.
- Error behavior is uniform. A failed call returns the `JsonRpcError` object; a service
  that ends with errors returns code `500` with HTTP 500. See [Errors](/api-reference/errors).

For the transport contract used by all methods above, see [JSON-RPC transport](/api-reference/json-rpc).
