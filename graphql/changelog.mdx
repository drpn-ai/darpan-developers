## Darpan 3.1.0

- Every API key expires. A key lasts at most 90 days from when it is created or rotated (`gql.apiKey.maxDays` on a self-hosted instance); a key created without an expiry date gets the maximum, and a later date is refused. Keys created earlier without an expiry date keep working until they are rotated or disabled. See [Authentication](/graphql/authentication#get-a-key).
- Each key records the user who created it, and creating, rotating or disabling a key writes an admin audit log row.
- On the signed-in session endpoint, a caller profile's product-store scope narrows the tenant's data instead of replacing the tenant condition. The API-key endpoint is unchanged.
- The reference pages are regenerated from the 3.1.0 schema, which includes the 3.0.0 change below.

## Darpan 3.0.0

- A finding is `open` or `fixed`; there is no `pending` state. `AuditSummary`, `CategoryCounts` and `FindingCounts` drop `pending`, `FindingStatus` drops `pendingUntil`, and `StatementCheck` drops `graceDays`. `newToday` counts findings first found that morning and still open. A query that selects a removed field fails validation, so remove those fields from saved queries.

## Darpan 2.1.1 (2026-10-27)

- Tenant administrators can create API keys, and a key is always for the tenant its creator is signed into.
- The GraphQL and API-key paths refuse cookies and answer CORS without credentials. `developers.drpn.ai` is an allowed origin, so the explorer can run your own key.

## Darpan 2.1.0 (2026-10-26)

- `auditReport` and `auditFinding` queries: audit runs over GraphQL, in the `darpan.audit.report/v1` and `darpan.audit.finding/v1` shapes.
- `category(id:)` on the audit report and `statement(id:)` on a category: one element by id, `null` when there is none.
- `findings` query: every finding of the key's tenant, paged, with `query:` keys `audit`, `statement`, `category`, `state`, `period` and `firstFound`, sorted by `FIRST_FOUND` or `STATEMENT`.
- API keys can be rotated with a grace period, disabled, and listed by an administrator.
- Every type, field and argument in the schema has a description.
- An audit query explains an expected refusal in plain words; other failures no longer show internal detail.
